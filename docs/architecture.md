# Architecture

Explanation of the project organization and how both apps communicate with each other.

## Shape

```txt
my-geek-hub/
├── backend/        Express REST API
├── frontend/       Next.js app
├── shared/         Zod schemas and types used by both apps
├── docs/           Project documentation (this folder)
├── .claude/        AI tooling: skills, hooks, subagents and commands
├── .planning/      AI workflow artifacts (GSD)
```

- `backend/` → Express REST API with TypeScript.
- `frontend/` → Next.js app.
- `shared/` → Zod schemas and types used by both apps. `zod` is installed in the root `package.json` (the only root dependency), so both apps resolve the same copy. Not a workspace.
- `.claude/` and `.planning/` → AI implementation to optimize the development process (see [AI in the project](#ai-in-the-project)).

## How they communicate

```txt
frontend (Next.js) ──HTTP/JSON──▶ backend (Express) ──▶ PostgreSQL
                                        │
                                        └──proxy──▶ External APIs (Tenrai, RAWG)
```

1. The **frontend** only talks to the **backend**, through REST requests with JSON.
2. The **backend** stores the user data (accounts, bookmarks, ratings) in **PostgreSQL**.
3. To search animes, mangas and games, the backend works as a **reverse proxy**: it forwards the request to the external API and returns the answer to the frontend.

The frontend never calls the external APIs directly. This way, the backend controls rate limits, cache and headers in one place.

## Backend

The backend is organized by **feature**. Each feature lives in `backend/src/api/<feature>/` and follows the same layers:

```txt
routes → controller → service → database
```

| Layer | Responsibility |
|---|---|
| `*.routes.ts` | Defines the paths and middlewares (auth, validation). |
| `*.controller.ts` | Reads the request, calls the service and sends the response. |
| `*.service.ts` | Business logic and database queries. |

Current features: `auth`, `users`, `bookmarks` and `ratings`.

Full breakdown of each folder: [backend/architecture.md](backend/architecture.md).

Other folders in `backend/src/`:

| Folder | Content |
|---|---|
| `config/` | Database, env vars, proxy probes and rate limits. |
| `constants/` | Fixed values (API URLs, status messages, etc). |
| `db/drizzle/` | Table schemas and relations (Drizzle ORM). |
| `libs/` | JWT helpers. |
| `middlewares/` | Authentication, validation and error handling. |
| `types/` | Shared TypeScript types. |
| `utils/` | Logger, response helpers and async wrappers. |

### Proxy

The proxy is the exception to the layers above: it has **no controller or service**, it only forwards requests.

```txt
backend/src/api/proxy/
└── tenrai/
    ├── tenrai.proxy.ts        Proxy factory for the Tenrai API
    ├── tenrai.helpers.ts      Path helpers shared by the Tenrai scopes
    ├── animes/
    │   └── animes.routes.ts   Routes mounted at /api/animes
    └── mangas/
        └── mangas.routes.ts   Routes mounted at /api/mangas
└── rawg/
    ├── rawg.proxy.ts          Proxy factory for the RAWG API (adds and hides the API key)
    └── games/
        └── games.routes.ts    Routes mounted at /api/games
```

- Each external API is a **target** (e.g. `tenrai`), and each media type is a **scope** (e.g. `animes`).
- Rate limits follow the official limits of each API (`config/rateLimit.ts`). RAWG Free only has a monthly quota (20,000 requests), so it is split into a daily limit.
- In development, the backend tests each external API on startup and prints the result (`config/proxy.ts`).

| Target | Scope | Status |
|---|---|---|
| Tenrai (MyAnimeList data) | Animes | Implemented |
| Tenrai (MyAnimeList data) | Mangas | Implemented |
| RAWG | Games | Implemented |

## AI in the project

The project uses AI tools to help on development. They don't run in production; they only support who is coding.

| Folder | Purpose |
|---|---|
| `CLAUDE.md` | Guides for AI agents (root and `backend/`). |
| `.claude/skills/` | Project skills, e.g. `proxy-route` (add a new proxy scope) and `doc-reviewer` (keep `docs/` updated). |
| `.claude/agents/`, `.claude/commands/`, `.claude/hooks/` | Subagents, commands and hooks from the GSD workflow. |
| `.planning/` | Artifacts generated by GSD, like the automated codebase snapshot. |
| `graphify-out/` | Knowledge graph of the code, used to understand how files connect. |

The files in `.planning/` and `graphify-out/` are generated automatically. When they differ from `docs/`, **`docs/` is the source of truth**.
